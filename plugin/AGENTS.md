# plugin/AGENTS.md

## Purpose

The Tern package: the only directory linked into Tern (`tern plugin link plugin`). Everything that runs inside Tern lives here.

## Ownership

- `plugin.toml`: manifest declaring the `workspace` block, the `status`, `diff`, `show` and `oplog` lenses, and `styles.css`
- `gb.luau`: shared by both halves: `gb.root` (managed-folder detection), `gb.run` (async `but` runner), JSON → model helpers, `gb.board_path` (where the drag-and-drop board lives)
- `host.luau`: host half: the workspace block (top bar with view tabs and sync chips; lanes, graph, stacks, branches and board views; the diff shown in place; sheets; actions including `f` pull and the board's squash, uncommit, amend-into, discard and redo), and the drag-and-drop board's Markdown and key file (`sync_board`) and its `native_drop` events
- `styles.css`: the workspace views' styles, every selector scoped to `[data-surface="plugin.gitbutler.workspace"]` (plugin sheets are window-global). No `ch` unit in Tern CSS: use `calc(var(--sf-cw) * N)`. Naming a stylesheet in the manifest before the file exists makes the plugin unusable until Tern restarts
- `lenses.luau`: command lenses plus the `spawn` filter (`BUT_THEME`, `BUT_PAGER`)
- `parse.luau`: pure readers for `but`'s human output, used only by the lenses
- `width.luau`: pure terminal cell width (East Asian wide, emoji sequences, zero-width marks) that sizes the workspace dock. Its range tables are generated from the Unicode UCD and emoji-data.txt (sources named above the tables); regenerate them, don't hand-edit ranges
- `window.luau`: window half: status segment, palette commands and keys (including `but setup --init`, `but tui` in a picture-in-picture pane, `but gui`, and the drag-and-drop board's opener and 400 ms watcher), `new_git_block` override, git-block warning
- `drag.luau`: pure diff of two drag-and-drop board reads (`drag.moved`, `drag.same_lanes`): which card one drag moved and next to what; a change to the lanes themselves is never a drag
- `check.luau`: runnable assertions for `parse.luau`, `width.luau` and `drag.luau`
- `check-layout.py`: behavioral layout harness for the workspace views (runs `host.luau` against fixture status JSON; `python3 check-layout.py` must print `assertions passed`)
- `tern.d.luau`: generated by `tern plugin types plugin`; never hand-edit

## Local Contracts

- Read GitButler state only with `but … --json`. The one exception is `lenses.luau`/`parse.luau`, which read the human text of a command the user typed (user-approved).
- Every write goes through `but` via `gb.run`. Never call raw git, and never use `cx.git` mutations (`stage`, `commit`, `checkout`, `stash_*`, `create_branch`).
- Host handlers have a 2 s budget: start processes only with `gb.run` (async, `timeout_ms`). Never block or loop on I/O.
- Window handlers have a 50 ms budget, and chrome formatters have 4 ms. Formatters read caches only; they never touch disk or processes.
- A window `cx` expires when its handler returns. Async callbacks that need one (toasts, layout) get a fresh one from `tern.timer(0, function(tcx) … end)`.
- Every surface uses `gb.root` to decide whether a folder is GitButler-managed. Don't add a second check.
- `parse.luau`, `width.luau` and `drag.luau` stay free of `tern` so `luau check.luau` can run them.
- Host-only APIs (`tern.block`, `tern.lens`, `tern.pane`) stay out of `window.luau`, and window-only APIs (`tern.command`, `tern.chrome`, `tern.route`, `cx.session`) stay out of the host files.
- Board drops, drag-and-drop board drags (`native_drop`) and right-click items run the same action functions as the keys, through the same confirm and push-state guards; never a second, unguarded path. Right-click item ids are plain labels mapped by `MENU` (Tern shows the id as the label); the row comes from the event's node id. The drag-and-drop board file is generated output in the plugin data folder: the host rewrites it from status, and nothing reads user edits back from it except a card's lane and place.
- Every user-facing block action has a `tern.command` in `window.luau` `ACTIONS` whose id maps through host `NAMED` to an `ACTIONS` key or `OPS` op; `run_action` is the one dispatch for palette commands, the user's `settings.json` `keybinds` (`plugin.gitbutler.<id>`) and board buttons. Command ids are a user-facing contract: never rename or drop one silently, and list each in the README's Keys table. Default chords are only ⌥⇧⌘G (open) and ⌥⇧⌘T (tui), the user's choice; everything else ships unbound. Adding a default chord needs asking first (root `AGENTS.md`), and after one, check `~/Library/Logs/Tern/tern.log` for `plugin bind left out` (the preset owns ⌥⇧⌘B and ⌥⇧⌘S).
- `move` (move to a branch, reorder) stays refused while an uncommitted file shares a path with the moved change, checked when the action starts and again on a fresh `status -f --json` right before `mutate` (`fresh_move`; polling pauses while a sheet is open): a failed `but` 0.22.3 move drops the commit and those changes with no oplog entry (`DESIGN.md` finding 6).
- Follow [DESIGN.md, Surfaces](../DESIGN.md#surfaces) for the inline diff's identity and refresh lifecycle.
- Mutations invalidate in-flight status reads; see `mutate` in `host.luau` for the read guard and [DESIGN.md, JSON fields relied on](../DESIGN.md#json-fields-relied-on) for pull result verification.
- Sync wording follows GitButler's own: the desktop app's branch labels (`gb.STATUS_TEXT`), its header's `N upstream commits`, and `but pull`'s `Up to date`. Don't invent status terms; a new state takes GitButler's name for it.

## Work Guidance

- Every file is `--!strict` Luau. Set node props through a local (`local p = node.p or {}; …; node.p = p`).
- Destructive actions (undo, oplog restore, unapply, land, history rewrites) open a `confirm` sheet showing the exact `but` command, with `danger = true`. Danger sheets accept only an explicit `y`.
- Report every outcome with `notify()` (dock line plus a toast) and run every `but` write through `mutate()` (start and result toasts with the command line). Don't set `state.notice` directly for an outcome the user should see; only the `v` view hint does that.
- Pass `but` arguments as an argv list (no shell). Mutations add `--json` and are checked by exit status.
- Async callbacks must check liveness (`running[pane] == state` / `pane_alive`) before touching state or sending effects.
- Saving any file here reloads every plugin in the user's real Tern. A reload that fails mid-edit kills open blocks. To test a deliberately broken build, link a copy (`cp -R plugin /tmp/gbp`) into the isolated Tern instead.
- Testing the board with `tern ctl --control … click X Y` (window pixels; a third arg `right` right-clicks): a hidden test window delivers clicks and renders seconds late, so wait for the result before clicking again. It also keeps a new block at 80×24 until a relaunch restores it at its real size.

## Verification

- `cd plugin && luau check.luau` (must print `parse: ok`)
- `cd plugin && python3 check-layout.py` (must print `assertions passed`) after any change to the views, the top bar or height budgets
- Syntax check: follow root `AGENTS.md`, Commands (`.no-mistakes.yaml` owns the script).
- Smoke each change in the isolated Tern (root `AGENTS.md`, Testing)
